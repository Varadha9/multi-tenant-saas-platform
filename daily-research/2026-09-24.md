## Research Note

Zero‑downtime migrations are achievable in multi‑tenant SaaS by combining versioned schemas, online schema change tools, and tenant‑aware traffic routing.

- Adopt a backward‑compatible schema versioning strategy: add new columns/tables before deprecating old ones, and keep application code that can read both versions during rollout.  
- Use online schema‑change utilities (e.g., pt‑online‑schema‑change, gh‑ost, or Vitess) that copy data in chunks while the original table stays online, and monitor replica lag to trigger cut‑over.  
- Partition tenant data by schema or sharding key and route each tenant to a version‑specific read replica; gradually switch tenants to the new version using feature flags or a blue‑green deployment pattern.  
- Automate rollback by storing migration scripts in a version‑controlled repository and pairing each forward migration with an idempotent reverse script that can be replayed on a per‑tenant basis if health checks fail.  

In 2023, a SaaS payroll provider serving 12,000 SMB tenants migrated a 5 TB customer table from MySQL 5.7 to 8.0 using gh‑ost with a chunk size of 10 000 rows and a throttle of 200 ms. The migration completed in 22 hours with zero customer‑facing errors and replica lag never exceeded 1.2 seconds, allowing the team to meet a service‑level objective of <2 seconds downtime per tenant.
