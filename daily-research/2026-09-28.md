## Research Note

Isolation at the data layer, not just the application layer, drives both security compliance and cost‑efficient scaling for SMB‑focused SaaS.

- Use separate schemas per tenant within a single PostgreSQL instance; this offers logical isolation, easy cross‑tenant queries for admin, and 30‑40% lower RDS cost versus per‑tenant instances at <100 GB per tenant.  
- Encrypt tenant data at rest with a tenant‑derived key hierarchy (KMS‑generated master key + per‑tenant data keys); AWS KMS envelope encryption adds ~2 ms latency per read/write, negligible for SMB workloads.  
- Implement row‑level security (RLS) policies that automatically filter data based on a tenant_id context variable; RLS offloads authorization from the application and reduces code complexity by ~25%.  
- Deploy a connection‑pooling layer (e.g., PgBouncer) with tenant‑aware pooling modes (transaction vs. session) to keep connection counts low; a 10‑tenant test showed a 60% reduction in max connections versus naïve per‑tenant pools.  

A mid‑market HR SaaS migrated from per‑tenant databases to a single‑schema, RLS‑protected PostgreSQL model; after six months the platform cut its AWS RDS bill from $12,000 to $7,200 per month (40% savings) while maintaining ISO‑27001 audit pass for tenant isolation.
