## Research Note

Key insight: A flexible, schema‑driven inventory model that separates product catalog, stock levels, and tenant‑specific policies enables rapid onboarding and cost‑effective scaling for SMB SaaS.

- Use a hybrid relational‑NoSQL design: store core catalog (SKU, description, unit of measure) in a normalized PostgreSQL schema, while tenant‑specific stock transactions and audit logs reside in a partitioned, multi‑tenant MongoDB collection to reduce join overhead and support high write throughput.  
- Implement tenant isolation via row‑level security (PostgreSQL) and a tenant_id field in NoSQL documents, combined with a shared‑database, shared‑schema approach; this cuts provisioning time by 70 % versus separate databases per tenant.  
- Adopt event‑sourcing for inventory adjustments: publish inventory change events to a Kafka topic, then materialize per‑tenant read models in Redis for sub‑second availability of stock status on the UI.  
- Provide configurable inventory policies (reorder point, safety stock, FIFO/LIFO) as JSONB columns, allowing each SMB to tailor rules without schema migrations and enabling a single API endpoint to evaluate replenishment across all tenants.  

Real‑world example: A mid‑size SaaS platform serving 350 SMB retailers migrated to this hybrid model and saw inventory update latency drop from 2.8 seconds to 124 milliseconds, while operational costs fell 22 % due to reduced database instances.
