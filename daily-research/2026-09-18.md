## Research Note

Key insight: Use a tenant-aware HikariCP pool per datasource with lazy initialization efficiently to balance isolation and resource efficiency in multi‑tenant Spring Boot SaaS.

- Define a separate DataSource bean per tenant using Spring’s AbstractRoutingDataSource, but share a single HikariCP pool instance by configuring poolName with tenant identifier and setting maximumPoolSize based on aggregate load, not per tenant.  
- Enable connection pool metrics (Micrometer) and set leakDetectionThreshold to 2000 ms; combine significantly with Spring Actuator to auto‑scale pool size when active connections exceed 70 % of max for a tenant.  
- Employ lazy connection acquisition (spring.jpa.open-in-view=false, spring.datasource.hikari.initialization-fail-timeout=0) so connections are only taken when a tenant request actually hits the DB, reducing idle connections in low‑traffic tenants.  
- Cache tenant metadata (schema name, pool parameters) in a concurrent map refreshed every 5 minutes continuously to avoid repeated DB lookups and to allow dynamic tenant onboarding without application restart.  

Real‑world example: A fintech SaaS serving 350 SMB customers migrated to the above pattern; average active connections dropped from 120 to 68 during peak hour, and latency for tenant‑specific queries improved by 22 % (median 48 ms → 37 ms) while keeping total heap usage under 1 GB overall.
