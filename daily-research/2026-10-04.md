## Research Note

Subdomain‑based routing provides isolation and brandability while keeping DNS management simple for SMB‑focused SaaS.  

- Deploy a wildcard DNS entry (e.g., *.app.example.com) pointing to the load balancer; this eliminates per‑tenant DNS updates and allows instant provisioning of new customers.  
- Configure the web server (NGINX, Apache, or Envoy) to route based on the Host header, mapping each subdomain to the same application instance but injecting a tenant_id into the request context.  
- Use a centralized tenant lookup cache (e.g., Redis) keyed by subdomain to retrieve configuration (DB connection, feature flags) in <5 ms, avoiding repeated DB hits on every request.  
- Terminate TLS with a wildcard certificate (or multi‑SAN cert) at the edge; this reduces handshake latency by ~15 % versus individual certs and simplifies certificate renewal across tenants.  

Example: FastTrack CRM migrated its onboarding flow to subdomain routing (client1.fasttrack.io, client2.fasttrack.io) and measured a 22 % drop in average page‑load time—from 2.3 s to 1.8 s—because tenant‑specific assets could be cached per host, while new tenant activation time fell from 30 minutes (manual DNS) to under 2 minutes (automatic wildcard). The approach also lowered SSL certificate management overhead by 80 %, as only one wildcard cert needed renewal annually.
