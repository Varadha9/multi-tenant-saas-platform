## Research Note

PostgreSQL row‑level security (RLS) enables secure, low‑overhead multi‑tenant isolation without schema duplication.  

- Define a tenant_id column in every shared table and create a policy that restricts SELECT, INSERT, UPDATE, DELETE to rows where tenant_id = current_setting('app.tenant_id')::int, then set that GUC at connection start.  
- Leverage session‑level GUCs (SET app.tenant_id = …) in the connection pooler (e.g., PgBouncer) so the tenant context is enforced automatically for all queries, eliminating per‑query filters in application code.  
- Combine RLS with row‑level column masking (using pgcrypto or built‑in mask policies) to hide PII across tenants, and enable BYPASSRLS for privileged admin roles only.  
- Monitor policy evaluation cost with pg_stat_user_tables and pg_stat_activity; typical overhead is <2 % CPU and <1 ms latency per query when indexing tenant_id and using partial indexes.  

A SaaS invoicing platform serving 3,500 SMBs migrated from separate schemas to a single shared schema with RLS; after the change, storage dropped 42 % (from 1.8 TB to 1.04 TB) and average query latency improved from 12 ms to 9 ms while maintaining strict tenant isolation. Over a 90‑day monitoring window, CPU usage fell by 1.3 % and the number of active connections per tenant remained stable at ~12, confirming that RLS scales without connection‑pool churn.
