## Research Note

Feature flags (also called feature toggles) are a deployment technique that decouples code deployment from feature release, making them essential for gradual module rollouts in multi-tenant SaaS platforms.

Key insight: Feature flags let you ship code to production without activating it, enabling per-tenant module rollouts with zero downtime and instant rollback capability.

- Store feature flag state in the database per tenant (tenant_id + flag_name + enabled), not in config files — this allows runtime toggling without redeployment and scales to thousands of tenants independently.
- Implement flag evaluation at the middleware layer, not in business logic — a single checkModuleEnabled(tenantId, moduleName) guard before routing prevents unauthorized access even if UI is bypassed.
- Use percentage-based rollouts for new modules: activate for 5% of tenants first, monitor error rates and performance, then gradually increase — this limits blast radius of bugs to a small cohort.
- Combine feature flags with audit logs — every flag change (who enabled what module for which tenant, and when) should be recorded, giving you a full rollout history and compliance trail.

Real-world example: LaunchDarkly reports that teams using feature flags reduce mean time to recovery (MTTR) from production incidents by 97% — from hours to under 5 minutes — because rollback is a single flag flip rather than a code revert and redeploy cycle.
